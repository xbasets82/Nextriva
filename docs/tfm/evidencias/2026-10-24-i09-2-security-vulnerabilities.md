## Revisión, limitaciones y validación manual

Solo cambiaron el arranque de API y su prueba HTTP; no se añadieron paquetes, migraciones, endpoints, permisos, secretos ni datos. El baseline quedó intacto. La excepción alta de Multer sigue temporal y no debe confundirse con “cero vulnerabilidades”: hay cero críticas y un aviso alto aprobado vigente. No se atribuye prueba de explotación a una ruta de subida que la aplicación no tiene.

Pendiente de decisión para una mitigación agregada del límite por IP, por el impacto en redes compartidas. Pendiente de confirmar el proxy/origen de despliegue antes de CSP/HSTS. La ejecución E2E intermitente y los módulos de dominio por debajo del objetivo de ramas se mantienen visibles. No se realizaron validaciones manuales con VoiceOver, Safari ni Firefox y no se declara conformidad WCAG completa.

Con la API local iniciada en el puerto configurado (por ejemplo 4317), validar cabeceras con:

```sh
curl -sSI http://127.0.0.1:4317/api/health | rg -i 'HTTP/|x-content-type-options|x-frame-options|referrer-policy|x-powered-by'
```

La respuesta debe incluir `nosniff`, `DENY` y `no-referrer`, y no debe incluir `X-Powered-By`. Esta revisión local no comprueba HSTS ni CSP en el proxy de producción.

Herramientas observadas: Node.js 24.22.0, pnpm 10.34.7, Vitest 5.0.5, Prisma 7.10.1, NestJS 12.0.3, PostgreSQL temporal y Playwright/Chromium. No se reconstruyeron resultados TDD históricos.
