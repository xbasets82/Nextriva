## Seguridad, integridad y revisión

El backend revalida actor, vínculo, estado, versión y elegibilidad dentro de la transacción. Un UUID privado produce 404; una acción sobre recurso visible sin permiso devuelve 403; ausencia de sesión 401. Rechazos, versión obsoleta y fallo de actividad conservan responsable, versión e historial. El error técnico permanece 503 seguro, sin detalles internos. El cliente usa el contrato generado, CSRF y JSX de texto; no guarda credenciales ni amplía permisos.

Las pruebas comprueban asignación/reasignación, ADMIN sin vínculo, MANAGER vinculado, COLLABORATOR denegado, inactivo/no vinculado/desconocido, null, campos extra, promoción archivada, pendiente/cerrada, versión concurrente, FK, rollback de actividad, visibilidad y comentarios del responsable, revocación tras reasignar/retirar y protección I02 antes y después del cierre. Las carreras usan `pg_blocking_pids`, no sleeps para fijar orden. No se implementan endpoints de cierre para preparar fixtures.

2. Entrar con ADMIN o MANAGER vinculado, abrir una incidencia abierta/en curso y elegir un responsable activo. Guardar, recargar y comprobar nombre y persistencia.

5. Intentar desactivar/degradar/retirar un responsable con incidencia no cerrada: conflicto y datos conservados. Reasignar antes y repetir la operación autorizada.
6. Comprobar teclado, foco de validación/guardado y ancho móvil. VoiceOver, Safari y Firefox permanecen pendientes; no se declara conformidad WCAG completa.

Las pruebas preparan estados cerrados/pendientes con fixtures PostgreSQL temporales: no adelantan la máquina de estados.
