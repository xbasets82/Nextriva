# Rediseño de cabecera, navegación y cierre de sesión

Fecha: 25/10/2026. Issue [#91](https://github.com/xbasets82/Nextriva/issues/91), aprobada. Rama `feat/web-header-navigation`, creada desde `main` actualizado en `0a7be7bf837673f728eaf1c224cf719afbfd96ed`.

## Alcance y decisiones

La cabecera autenticada presenta la identidad NEXTRIVA a la izquierda, navegación centrada independientemente del ancho lateral y logout como botón con icono en el extremo derecho. En móvil, la navegación ocupa una segunda fila. Las pestañas mantienen la visibilidad por rol vigente; la ruta resuelta marca `aria-current="page"` y el indicador visual activo. No cambian rutas, permisos, API, sesiones, CSRF ni persistencia.

El botón de logout conserva el controlador y la operación existentes de `SessionGate`, con `type="button"`, nombre accesible, foco visible y estados de carga/error. Se utilizó SVG inline porque el proyecto no dispone de una biblioteca de iconos existente. No se añadió tooltip: no hay un componente Tooltip aprobado/disponible en el frontend. Las transiciones respetan `prefers-reduced-motion`.

Durante validaciones concurrentes aparecieron dos fallos no relacionados con estos archivos: una prueba existente de foco de comentarios y otra de carga de promociones. Typecheck también detectó inicialmente un acceso `.type` no soportado por `HTMLElement` en una prueba nueva; se cambió a `getAttribute('type')` y el typecheck final pasó. Prettier pidió formato en `App.tsx`; se aplicó y `format:check` final pasó.

## Accesibilidad y límites

La navegación está etiquetada como `Principal`; el enlace activo usa `aria-current="page"`. El botón de logout tiene nombre accesible, es un botón explícito y ofrece foco visible. Playwright comprobó la activación mediante espacio y que se conserva la revocación real de sesión. Los tamaños probados no presentan desbordamiento horizontal y la navegación queda centrada en el viewport.

No se afirma conformidad WCAG completa. La revisión visual humana, VoiceOver, Safari y Firefox quedan pendientes. No se modificó ni generó contrato HTTP; OpenAPI se verificó como control de coherencia. Integración API separada no aplica porque el cambio es exclusivamente de presentación; la E2E sí ejercitó API y PostgreSQL temporal mediante el runner seguro.
