## Motivo y evidencia previa

El job «Auditoría pnpm» de la CI en `main` falló en el run [39737442637](https://github.com/xbasets82/Nextriva/actions/runs/39737442637/job/119686377447), en el paso de evaluación del baseline. La auditoría encontró los dos avisos moderados en `@vitest/mocker@5.0.0`, transitivo de Vitest. La instalación congelada, las 35 pruebas del evaluador y el otro job de calidad, pruebas y build pasaron.

La última CI verde de la PR #44 fue el run [39653096469](https://github.com/xbasets82/Nextriva/actions/runs/39653096469). Allí el evaluador aceptaba las tres excepciones exactas existentes y no registraba los dos avisos de Vitest. El Issue #18 es independiente: cubre los avisos de Prisma `deepmerge-ts` y `mysql2`, no Vitest.

Los avisos describen riesgos en servidores de desarrollo accesibles por red; no implican que Vitest se use como dependencia de producción. La documentación de los mantenedores señala `@vitest/mocker` 5.0.3 como corregido. Se eligió Vitest 5.0.5, disponible al realizar el cambio, conservando la versión mayor. La versión admite Node 24 y Vite 8, que coinciden con los valores fijados en el proyecto. Referencias: [GHSA-qxg6-89mg-rqv8](https://github.com/vitest-dev/vitest/security/advisories/GHSA-qxg6-89mg-rqv8), [GHSA-xp26-3454-mjgp](https://github.com/vitest-dev/vitest/security/advisories/GHSA-xp26-3454-mjgp), [manifiesto de Vitest 5.0.5](https://github.com/vitest-dev/vitest/blob/v5.0.5/packages/vitest/package.json).

Los dos intentos de entorno previos a la ejecución correcta de cobertura API fueron detenidos por los guardas del runner: el primero carecía de `TEST_DATABASE_URL`; el segundo usó credenciales sintéticas no coincidentes con el PostgreSQL de pruebas ya activo. Ninguno alcanzó a crear una base. Después de la autorización explícita, se cargó el entorno de prueba local sin imprimir credenciales ni pasar `DATABASE_URL` al runner.

El primer fallo de cobertura API fue una carrera entre pruebas paralelas: `auth.persistence.integration.test.ts` crea y limpia `i02_1_login_gate`, mientras `database.integration.test.ts` comprueba las tablas. La repetición API completa y una repetición posterior del comando agregado pasaron sin modificar expectativas ni reducir pruebas. El comportamiento intermitente queda registrado como riesgo residual de la suite.
