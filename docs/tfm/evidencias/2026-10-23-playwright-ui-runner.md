# Herramienta — Runner Playwright UI con PostgreSQL temporal

Fecha: 23/10/2026. Issue [#64](https://github.com/xbasets82/Nextriva/issues/64), aprobada. Rama local `codex/playwright-ui-test-runner`, creada desde `main`/`origin/main` en `add08e8c85f57aa9358503089f66e682bfa1f45b`.

## Alcance y decisiones

Se añadió `mise exec -- pnpm --filter @nextriva/api test:e2e:ui`, que reutiliza `scripts/test-integration.mjs`, la validación local de `TEST_DATABASE_URL`, la configuración Prisma de test y el `playwright.config.ts` existente. El runner crea una base PostgreSQL temporal aleatoria, aplica las migraciones versionadas y mantiene el runner, los servidores API/web y esa base disponibles mientras Playwright UI permanece abierta. `test:e2e` conserva su comando y su ruta de limpieza actuales. No se modificaron tests de producto, `reuseExistingServer`, CI, dependencias ni esquema.

La modalidad interactiva usa procesos asíncronos, salida redactada por líneas aun cuando una credencial quede dividida entre bloques, reenvío de SIGINT/SIGTERM al grupo de Playwright y limpieza en `finally`. Un registro privado local, sin credenciales, enlaza el UUID de sesión con el nombre de una base temporal y el proceso. Una ejecución UI posterior recupera únicamente bases descritas por registros válidos y obsoletos, coordinándose con un advisory lock PostgreSQL; marcadores malformados, enlaces simbólicos, directorios inseguros y procesos activos se omiten. La UI reserva dos puertos loopback efímeros distintos cuando el usuario no especifica `NEXTRIVA_E2E_API_PORT` y `NEXTRIVA_E2E_WEB_PORT`; mantiene los overrides explícitos y libera las reservas antes de iniciar Playwright. El E2E normal no cambia. `reuseExistingServer: false` permanece intacto.

## Verificación real de UI y aislamiento

La primera ejecución normal de E2E encontró los puertos predeterminados `4317`/`5173` ocupados por servidores locales existentes. Playwright rechazó esos puertos sin reutilizarlos; no se detuvieron esos procesos. La repetición en los puertos alternativos `4517`/`5517` aplicó las siete migraciones a una base temporal y pasó 32/32 pruebas Chromium con API y PostgreSQL reales.

La interfaz Playwright UI se abrió realmente en Chrome for Testing. Tras finalizar la carga de la lista aparecieron los 32 casos E2E. Desde la barra lateral se ejecutó dos veces el test `Chromium creates and queries a promotion persisted with ordered phases`; ambas ejecuciones pasaron en la misma sesión de UI y base temporal. Así se comprobó la selección individual y la repetición sin recrear la base entre ejecuciones.

Durante la validación manual posterior se reprodujo que UI mostraba “No tests” cuando API/web ya ocupaban `4317`/`5173`: el panel de salida indicó que `/api/health` ya estaba en uso. La causa no era descubrimiento roto; Playwright rechazaba iniciar `webServer` con `reuseExistingServer: false`. Se añadió selección automática de puertos efímeros, exclusiva para `test:e2e:ui`. Una repetición del comando sin variables adicionales asignó puertos UI `54155`/`54156` y la UI enumeró los 32 tests. No se ejecutaron tests desde esta repetición diagnóstica; la ejecución doble de la prueba de promoción corresponde a la observación anterior descrita arriba.

En una sesión posterior volvió a aparecer “No tests” aunque los puertos dinámicos estaban activos. Playwright tenía marcada la opción **Show only changed files**; al desactivarla, la lista de pruebas apareció en la UI. No hizo falta cambiar código para resolver este filtro. El usuario confirmó después que las pruebas pasaban; en esta sesión no se ejecutó una prueba adicional desde la UI.

Se cerró la modalidad UI con Ctrl+C. El proceso devolvió 130, coherente con SIGINT; la limpieza terminó, una consulta que solo devolvió el conteo confirmó **0** bases `nextriva_test_i02_1_*`, el registro local terminó vacío y no quedaron los procesos identificados de esa sesión. `nextriva_dev` no se utilizó. No se probó una terminación forzada SIGKILL de procesos del sistema; la recuperación por registro obsoleto se probó con unitarias y cliente PostgreSQL simulado, por lo que una recuperación abrupta real queda pendiente de validación manual controlada.

## Uso manual

1. Desde la raíz, ejecutá `mise exec -- pnpm --filter @nextriva/api test:e2e:ui` en una terminal con Docker de test disponible y la configuración local validada de `TEST_DATABASE_URL`.
2. Esperá a que cargue la lista de tests; expandí el archivo, seleccioná un caso y pulsá **Run**. El filtro permite localizar pruebas por nombre. Las vistas de acciones, source, log, errors y console ayudan a inspeccionar fallos.
3. Repetí el caso en la misma UI para conservar la misma base durante la sesión.
4. Cerrá con Ctrl+C en la terminal. La salida 130 indica que se recibió SIGINT; confirmá que el runner terminó y ejecutá nuevamente si necesitás inspeccionar que la base temporal ya no existe.

El comando `test:e2e` continúa ejecutando la suite completa una vez y elimina la base al finalizar; `test:e2e:ui` conserva API, web y base durante la sesión interactiva. La UI se observó en macOS/Chrome for Testing. No se afirma compatibilidad visual manual con otros navegadores ni recuperación tras SIGKILL real; esos dos puntos permanecen pendientes.
