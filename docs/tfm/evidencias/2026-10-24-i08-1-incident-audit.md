## Excepción temporal para Multer — APLICADA TRAS APROBACIÓN EXPRESA

En la revisión del código no se encontraron rutas de subida, `FileInterceptor`/variantes ni configuración `fileFilter` en `apps/api/src` o `apps/api/e2e`. El aviso requiere un flujo de carga multipart con `fileFilter` asíncrono; esta ausencia reduce la exposición funcional observada, pero no elimina la vulnerabilidad del paquete ni el resultado de auditoría.

Para desbloquear I08.1 mientras Nest publica un adaptador corregido, se aprobó y aplicó una excepción única y exacta de 30 días, con vencimiento `2026-11-23T00:00:00.000Z`.

```json
{
  "ghsa": "GHSA-q7qp-rjg7-q26m",
  "package": "multer",
  "version": "2.4.0",
  "path": "apps__api>@nestjs/platform-express>multer",
  "severity": "high",
  "expiresAt": "2026-11-23T00:00:00.000Z",
  "justification": "Excepción temporal hasta que @nestjs/platform-express publique una versión compatible que dependa de multer >=2.5.0. Nextriva no tiene rutas de subida ni fileFilter asíncronos. Revisar releases de NestJS semanalmente, retirar la excepción apenas exista actualización corregida y no incorporar flujos de subida mientras siga vigente."
}
```

El riesgo residual es una denegación de servicio bajo una carga multipart que utilice `fileFilter` asíncrono. No se hallaron rutas multipart, interceptores de subida ni configuración `fileFilter` en `apps/api/src` o `apps/api/e2e`; esto reduce la exposición observada, pero no elimina la vulnerabilidad del paquete. Mientras la excepción siga vigente: no introducir endpoints de subida ni `fileFilter` asíncronos, revisar semanalmente las releases de NestJS y retirar la excepción inmediatamente cuando una versión compatible dependa de Multer `>=2.5.0`. La excepción cubre solo el GHSA, paquete, versión, ruta y severidad indicados; no cubre otros hallazgos.

El evaluador admite solo la combinación exacta del JSON anterior, rechaza excepciones adicionales o modificadas y falla desde la fecha de expiración. El baseline no permite ampliar esta excepción ni añadir otras sin una nueva aprobación.

## Seguridad, límites y validación humana

El comentario nunca se copia a la actividad. Actor y fecha no se aceptan desde el cliente. Rechazos de validación/autorización no crean eventos. Una falla en la escritura del historial provoca rollback del comentario y devuelve el error genérico existente. El baseline mantiene solo la excepción temporal de Multer descrita arriba.

No hay cambio visual, por lo que no se ejecutó validación manual de accesibilidad; VoiceOver y compatibilidad Safari/Firefox siguen pendientes para una validación global del producto. No se declara conformidad WCAG completa. La migración solo se aplicó a bases temporales; no se ejecutó en `nextriva_dev`.

Antes de considerar cerrado I08.1, revisar el diff y validar manualmente el detalle de una incidencia después de agregar comentario: debe aparecer `COMMENT_ADDED` ordenado, con referencia al UUID del comentario y sin incluir su cuerpo. La actividad no se representa aún en una pantalla específica de historial.
