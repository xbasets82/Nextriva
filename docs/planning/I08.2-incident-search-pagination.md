## Alcance aprobado

Ampliar `GET /api/incidents` con búsqueda por código/título y filtros por promoción, estado, prioridad, categoría y responsable actual. Los filtros se combinan con AND; código y título forman una condición OR. `q` se recorta, vacío equivale a ausencia y el máximo es 150 caracteres.

Paginación con `page=1`, `pageSize=20` por defecto y tamaño máximo 100. El orden es fijo `createdAt DESC, id DESC`. Respuesta: `{ items, page, pageSize, total, totalPages }`. Una página positiva que supere el número de páginas devuelve una página vacía con el total autorizado, no un error.

El ámbito se incorpora a la consulta antes de contar y paginar: ADMIN global; MANAGER según vinculaciones; COLLABORATOR según vinculación y autoría o asignación vigente. Ningún total ni elemento puede revelar incidencias fuera del ámbito. No se añade orden configurable, búsqueda avanzada, endpoint, entidad ni migración.

La interfaz incluye búsqueda, filtros, paginación, estados de carga/vacío/error, reintento, limpieza de criterios y navegación a detalle y regreso. Los valores de promoción y responsable se introducen como UUID, pues el alcance aprobado no añade endpoints de descubrimiento.

## Decisiones de contrato

- Parámetros permitidos: `q`, `promotionId`, `status`, `priority`, `category`, `assignedToId`, `page`, `pageSize`; los desconocidos se rechazan con HTTP 400.
- Identificadores validados como UUID y enums validados en servidor.
- Páginas y tamaños deben ser enteros decimales positivos; `pageSize > 100` y offsets no representables se rechazan con HTTP 400.
- Consultas Prisma parametrizadas con AND/OR; no se concatena SQL con datos del usuario. Los caracteres `%`, `_` y `\\` se escapan para conservar la búsqueda literal de subcadenas.
- El contrato OpenAPI define los parámetros y la forma de respuesta; los tipos web se regeneran desde OpenAPI.

## Pruebas previstas

- Unitarias Vitest para validación de parámetros, serialización y respuesta del cliente, filtros accesibles y estados de UI.
- Integración HTTP con PostgreSQL temporal real para combinaciones, alcance por rol, total filtrado, orden, paginación, páginas vacías e inputs inválidos.
- E2E Playwright con API y PostgreSQL temporales reales: aplicar/limpiar búsqueda, avanzar páginas, abrir detalle y regresar.
- Controles de OpenAPI/tipos, typecheck, lint, formato, build, cobertura y baseline de seguridad.

## Límites

La autorización se mantiene en servidor. No se añaden índices ni cambios de esquema; se reevaluarán solo con evidencia de rendimiento y aprobación. La verificación manual con lectores de pantalla y navegadores distintos de Chromium permanece pendiente; no se declara conformidad WCAG completa.
