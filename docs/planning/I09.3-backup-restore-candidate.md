# I09.3 — Backup, restauración y candidato

**Issue:** [#83](https://github.com/xbasets82/Nextriva/issues/83) · **Issue aprobado:** sí · **Estado de la implementación:** implementación local verificada en `codex/i09-3-backup-restore-candidate`, basada en `main` `2364e681`. No acredita publicación ni recuperación operativa.

## Alcance acordado

- Documentar la creación manual de un dump PostgreSQL custom de desarrollo, fuera del repositorio y con permisos privados.
- Verificar una copia sintética en PostgreSQL real: dump, restauración aislada, comparación de integridad y smoke query.
- Probar que un restore inválido no deja cambios parciales y que el runner elimina solo sus bases temporales.
- Revisar compatibilidad del cliente PostgreSQL, migraciones y reversión de aplicación.
- No hacer backup ni restaurar datos reales como parte de CI; no ejecutar en `nextriva_dev`, demo ni producción.

## Decisiones técnicas

| Tema                   | Decisión                                                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Herramientas           | `pg_dump` y `pg_restore` de `postgres:18.6-bookworm`, alineados con el servidor PostgreSQL del proyecto y evitando la versión de cliente distinta del runner GitHub. |
| Formato                | Archivo custom; salida de test fuera del repo con directorio `0700` y archivo `0600`.                                                                                |
| Destino de prueba      | Base PostgreSQL temporal única bajo el nombre permitido `nextriva_test_i09_3_<32 hex>`; la restauración no reutiliza la base origen.                                 |
| Atomicidad             | `pg_restore --exit-on-error --single-transaction --no-owner --no-acl`.                                                                                               |
| Extensiones            | Comparar las extensiones instaladas antes/después; las doce migraciones vigentes no declaran `CREATE EXTENSION`.                                                     |
| Rollback de aplicación | No hay cambio de esquema ni runtime. No se ejecuta rollback de datos ni se borran migraciones.                                                                       |
| Backfill               | No aplica: no hay migración ni reconstrucción de historia.                                                                                                           |

## Pruebas y evidencia

El comando confirmado en el manifiesto es `mise exec -- pnpm --filter @nextriva/api test:backup-restore`. El runner lee solo la configuración segura de test, rechaza `DATABASE_URL` heredada y elimina sus bases temporales al finalizar. GitHub Actions ejecuta esta verificación como paso obligatorio del job de integración.

La guía operativa está en [`../development/postgres-backup-restore.md`](../development/postgres-backup-restore.md). Los resultados observados y limitaciones se registran en [`../tfm/evidencias/2026-10-24-i09-3-backup-restore.md`](../tfm/evidencias/2026-10-24-i09-3-backup-restore.md).
